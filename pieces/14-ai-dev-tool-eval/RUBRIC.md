# Evaluation rubric for AI coding tools

This rubric is vendor-neutral. It names no product and states no vendor fact. You fill it in from
each vendor's own documents, which you read yourself on the day you score.

Each criterion is scored from 0 to 3 against the levels in its row. The weights are defaults.
`weights.json` holds the same IDs, groups, weights and gate flags, and the script reads that file.
A test fails if this document and `weights.json` disagree.

## How to score

- Score only from evidence you read. Record the document URL and the date you read it next to each
  score in your own copy. This example file does not carry those fields.
- Missing evidence scores 0, and your notes say the evidence is missing. Do not guess a higher level.
- A criterion marked gate blocks the tool when it scores 0. A blocked tool ranks below every tool
  that is not blocked, whatever its total.
- Before the pilot, set E1 to E3 to 0. Nobody has measured the tool yet. Re-score after the pilot.
- The script will not run on a partial scorecard. Every criterion needs a score for every tool.

## Weights

| Group                      | Criteria    | Total weight |
| -------------------------- | ----------- | ------------ |
| Data handling and security | A1 to A5    | 35           |
| Admin and governance       | B1 to B4    | 25           |
| Audit logging              | C1 to C3    | 15           |
| Cost                       | D1 to D3    | 10           |
| Measured productivity      | E1 to E3    | 15           |
| Total                      |             | 100          |

The weights sum to 100. Change them only in `weights.json`, and update this table and the weight
column in the same change. Write down why you changed them.

## Evidence limits

- A level describes a document or a test. A vendor's marketing page shows what the vendor claims.
  Score from the terms, the admin documentation and your own test.
- Rubric criteria say nothing about model quality. Measure that in your own tasks, if you need it.
